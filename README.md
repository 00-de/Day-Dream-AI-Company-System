# DayDream AI Company System v2.6.0

社長1人 ＋ AI社員23人による、次世代型AIエンターテインメント会社の統合ダッシュボードです。

- **フェーズ1**：2画面のUI（完了）
- **フェーズ2**：Firebase Auth（5アカウント・権限）＋ Firestore 連携（完了）
- **フェーズ3**：AI秘書を Groq / Gemini / OpenAI に接続（完了）
- **フェーズ4**：タスク管理＋Firebase Storage へのファイルアップロード（完了）
- **AI会議ルーム**：AI社員を集めて議論・議事録・タスク化 ← 追加しました

> アバター画像の作り方は `AVATAR_PROMPTS.md`、ログインアカウントは `ACCOUNTS.md`、AI接続は `AI_SETUP.md`、ファイル管理の設定は `STORAGE_SETUP.md` に詳しく書いてあります。

## フェーズ2でできるようになったこと

1. **社長ログイン** … メールアドレスとパスワードでログインします
2. **見るだけモード** … Firebase未設定でも全画面を確認できます（保存はこの端末の中だけ）
3. **データ編集** … ヘッダーの「データ編集」から、画面の数字・文章をその場で書き換えて保存
   - 経営数値（売上・利益・目標・達成率）
   - 予定・お知らせ（追加・削除もできます）
   - プロジェクト（進捗はスライダーで調整）
   - AI社員23人（担当・稼働状況・タスク数）
   - YouTube指標・次回ライブ
4. **リアルタイム同期** … パソコンで変更したらスマホ側も自動で書き換わります
5. **AI秘書チャット** … 保存したデータを見て答えるようになりました

## セットアップ（ターミナル不要）

### 手順1：Firebaseプロジェクトを作る

1. [Firebaseコンソール](https://console.firebase.google.com/) で「プロジェクトを追加」
2. 左メニュー **Authentication** → 「始める」 → **メール／パスワード** を有効にする
3. 「Users」タブ → 「ユーザーを追加」で、社長用のメールアドレスとパスワードを登録
4. 左メニュー **Firestore Database** → 「データベースの作成」→ 本番環境モードで作成
5. Firestore の **ルール** タブを開き、同梱の `firestore.rules` の中身を貼り付けて「公開」
6. 左メニュー **プロジェクトの設定** → 「マイアプリ」→ ウェブアプリを追加し、
   表示される `firebaseConfig` の6つの値を控えます

### 手順2：環境変数を登録する

**ローカルで動かす場合**
`.env.example` をコピーして `.env` という名前にし、6つの値を貼り付けます。

**Vercelの場合**
Vercel のプロジェクト → **Settings → Environment Variables** に、次の6つを登録します。

| 変数名 | 入れる値 |
| --- | --- |
| `VITE_FIREBASE_API_KEY` | apiKey |
| `VITE_FIREBASE_AUTH_DOMAIN` | authDomain |
| `VITE_FIREBASE_PROJECT_ID` | projectId |
| `VITE_FIREBASE_STORAGE_BUCKET` | storageBucket |
| `VITE_FIREBASE_MESSAGING_SENDER_ID` | messagingSenderId |
| `VITE_FIREBASE_APP_ID` | appId |

登録したら **Deployments → 最新のデプロイ → Redeploy** を押してください（環境変数は再デプロイで反映されます）。

> Firebaseのこの6つの値は、公開されても問題ない値なので `VITE_` を付けてOKです。
> OpenAI・Groq などのAPIキーは絶対に `VITE_` を付けないでください（フェーズ3で対応します）。

### 手順3：ログインドメインを許可する

Firebaseコンソール → **Authentication → Settings → 承認済みドメイン** に、
Vercelのドメイン（例：`your-app.vercel.app`）を追加してください。
これを忘れるとログインできません。

## サーバー機能（API）の構成

Vercelの無料プラン（Hobby）は、**サーバー機能を12個まで**しか置けません。
そのため、入口を1つにまとめて、中で振り分ける形にしています。

```
api/
├ index.js          ← 唯一の入口（/api?fn=chat のように指定）
├ _provider.js      AI呼び出しの共通処理
├ _search.js        Web検索の共通処理
└ _handlers/        実際の処理（12種類）
   ├ chat.js        AI秘書チャット
   ├ meeting.js     会議
   ├ meetingchat.js 会議中の発言
   ├ opinions.js    全社員の意見
   ├ agent.js       会場・スポンサー探し、調査
   ├ sns.js         SNS投稿文
   ├ check.js       公開前チェック
   ├ report.js      日報・週報
   ├ dev.js         開発の相談
   ├ craft.js       外部サービス用プロンプト
   ├ shots.js       MV絵コンテ
   └ image.js       Stability AI 画像生成
```

`_` で始まるファイル・フォルダは、URLとして公開されません。
機能を追加するときは `_handlers/` にファイルを足し、`index.js` に1行加えるだけです。
**これでいくつ機能を増やしても、Vercelの上限には当たりません。**

## フェーズ3でできるようになったこと

- AI秘書チャットが **Groq → Gemini → OpenAI** の順に自動フォールバックして接続します
- **APIキーはVercelのサーバー側（`/api/chat`）だけが読み込みます**。ブラウザには出ません
- APIキーが無くても **簡易応答モード** でそのまま使えます（保存中のデータを見て答えます）
- チャット相手を **AI社員10人から選べます**（AI秘書・AI社長・蓮AI・結衣AIなど）
- AIは、保存中の売上・予定・AI社員・ライブ・YouTubeの情報を見た上で答えます
- 設定画面で、いまどのAIに接続できているか確認できます

セットアップ手順は **`AI_SETUP.md`** を見てください。

### 環境変数（AI用・`VITE_` は絶対に付けない）

| 変数名 | 内容 |
| --- | --- |
| `GROQ_API_KEY` | Groq のAPIキー（おすすめ・無料枠が大きい） |
| `GEMINI_API_KEY` | Google Gemini のAPIキー |
| `OPENAI_API_KEY` | OpenAI のAPIキー |
| `ANTHROPIC_API_KEY` | Claude のAPIキー |

3つ全部は不要です。1つ登録すれば動きます。

### AIの使い分け（任意）

詳細は **`AI_ROTATION.md`** を参照してください。

| 変数名 | 内容 |
| --- | --- |
| `AI_ORDER` | 使う順番（例：`openai,groq,gemini`） |
| `AI_ROTATE` | `1` で呼び出しごとに交互に使用 |
| `AI_HEAVY` | 重い処理（会議・調査・レポート）だけ優先するAI |

**おすすめ**：軽い処理は無料のGroq、重い処理は課金済みのOpenAIに振り分けると、
費用を抑えつつ安定します（`AI_ORDER=groq,openai` ＋ `AI_HEAVY=openai`）。

## フェーズ4でできるようになったこと

- **タスク管理** … 経営ダッシュボードで、やること・担当AI社員・期限・優先度を登録。完了率と期限切れが自動で分かります
- **ファイルアップロード** … 画像・楽曲・動画・書類を Firebase Storage にアップロード。ドラッグ＆ドロップ対応

- 楽曲は音楽制作パネル、画像は画像生成パネルにライブラリとして並びます

設定手順は **`STORAGE_SETUP.md`** を見てください。
Firebaseコンソールで **Storage を有効化 → `storage.rules` を公開 → `firestore.rules` を更新** の3つが必要です。

## AI会議ルーム（画面③）

ヘッダーの **「会議ルーム」** から開けます。

1. **議題を入力**（例：「次のシングルの方向性を決めたい」）。議題の例ボタンからも選べます
2. **AI社員を2〜6人選ぶ**。それぞれの担当の立場から意見が出ます
3. **発言の回数（1〜3巡）を選ぶ**。1巡＝全員が1回ずつ発言
4. **「会議を開始する」** を押すと、発言が1つずつ順番に表示されます
5. 会議が終わると **議事録・決定したこと・次にやること** が自動でまとまります
6. 「タスクに登録」を押すと、そのまま **タスク管理** に入ります

- 発言中のAI社員は、上の参加者席が光ります
- 過去の会議は右側に一覧で残り、クリックすると読み返せます
- AIは売上・予定・プロジェクト進捗・ライブ情報を見た上で議論します
- APIキーが無い場合も、担当分野に応じた簡易的な会議が生成されます

### 人間メンバーの意見を入れる

会議ルームの左側に **「人間メンバーの意見」** パネルがあります。

小林さん（社長）・高木さん（企画・プロデュース）・太田さん（イベント運営）・
中尾さん（音響）・シュンさん（映像・配信）の5人から選び、意見を書いて追加します。

- 意見は会議の**冒頭に発言として表示**され、参加者席にも「🧑 お名前」が並びます
- AI社員は**必ず名前を挙げて応答**します（「高木さんが言われた〜について」のように）
- 頭から否定せず、実行するために足りない点や具体化する方法を補うようAIに指示しています
- **現場の事情（会場・機材・人手・予算）に関わる指摘は特に重く受け止める**よう指定しています
- 対応が必要な意見は「次にやること」に必ず入ります
- 意見は会議記録と一緒に保存され、過去の会議を開くと復元されます

人間メンバーの定義は `src/data/humans.ts` で変更できます。

### 会議中にチャットで発言する

会議が終わったあと、会議ログの下に**発言欄**が出ます。

1. 発言する人を選ぶ（小林さん・高木さん・太田さん・中尾さん・シュンさん）。**最大3人まで同時に選べます**
2. 選んだ人ごとに入力欄が出るので、それぞれの発言を書きます
3. 送信（**Ctrl + Enter** でも送れます）
4. 関係の深い担当のAI社員が **1〜3人**（選べます）その場で答えます

**複数人で発言した場合**、AI社員は全員の発言に名前を挙げて触れます。
意見が食い違う場合は、その違いを整理したうえで折り合いのつけ方を示します。
（例：中尾さん「低音を抑えたい」／高木さん「予算は30万まで」→ 両方を踏まえた案が返ります）

- **人間の発言は右寄せ・色付き**で表示され、AI社員の発言と区別できます
- これまでの会議の流れを踏まえて答えるので、話が噛み合います
- やり取りは**会議記録に保存**され、過去の会議を開くと読み返せます
- 「その予算は厳しい」「会場は200名まで」のような現場の指摘には、
  実現するために何が要るかを補って答えます

### 参加していないAI社員全員の意見を聞く

会議が終わると、議事録の下に **「参加していないAI社員の意見」** パネルが出ます。

「全員に意見を聞く」を押すと、その会議に出ていなかった社員（最大24人）全員から
決定内容への意見が集まります。

- 各意見に **賛成 / 条件付き / 懸念あり** の立場が付きます
- 上部に3つの数が集計されるので、社内の空気が一目で分かります
- **「懸念のみ」で絞り込めます**。反対意見だけを拾って確認できます
- AIには「全員賛成では意味がない。担当上引っかかる人ははっきり懸念を述べ、必ず代案を添える」と指示しています
- 集めた意見は会議記録に自動保存され、過去の会議を開くと読み返せます

Firestore に **`meetings`** コレクションが追加されています。
`firestore.rules` を更新版に貼り替えてください。

## MV画像 一括生成（Stability AI）

制作画面の「MV一括生成」から使います。詳細は **`MV_GENERATOR.md`** を参照してください。

1. 曲名・雰囲気・歌詞を入れる
2. 枚数（24〜72枚）と1枚の表示秒数（3〜8秒）、画質を選ぶ
3. AIが絵コンテを作る（時間・場面・英語プロンプト付き。手で直せます）
4. まとめて生成 → ZIPで保存（絵コンテ.txt付き）またはライブラリに登録

- **5秒×48枚＝約4分のMV**。費用は Core なら約220円です
- 失敗したカットだけ作り直せます。生成の途中中止もできます
- 全カットに同じ絵柄指定が入るので、統一感が出ます

環境変数 `STABILITY_API_KEY` が必要です（`VITE_` は付けない）。

## 葵AI・澪AIの実務（AI社員ボード）

### 葵AI：SNS投稿文を作る

X（旧Twitter）・Instagram・YouTube概要欄から選び、投稿したい内容を入れると、
**切り口の違う案を2〜5個**作ります。

- 媒体ごとの文字数・ハッシュタグの作法に合わせて書きます
- **文字数は実際に数え直して表示**します（140字超過は赤く出ます）
- 各案に「なぜこの書き方にしたか」と「投稿におすすめの時間帯」が付きます
- 予備のハッシュタグも提案されます（クリックでコピー）
- **「澪AIへ」ボタンで、そのまま公開前チェックに送れます**

### 澪AI：公開前チェック

SNS投稿文・歌詞・お知らせ・メールを選んで貼り付けると、公開前に確認します。

- **判定**：公開して大丈夫／直したほうがよい点あり／公開前に直して
- 観点は7つ（誤字・文法・読みにくさ・配慮・事実確認・個人情報・著作権）
- 各指摘に**該当箇所の引用・理由・修正案**が付きます
- **会社のデータと食い違う日付や数字も指摘します**
- 最後に、すべて反映した**修正版の全文**が出るのでそのまま使えます
- 問題が無ければ「指摘なし」と正直に返します（無理に指摘を作りません）

## AI社員に実際の仕事をさせる（Web検索）

**AI社員ボードの一番上**にあります。詳細は **`SEARCH_SETUP.md`** を参照してください。

| 仕事 | 担当 | できること |
| --- | --- | --- |
| ライブ会場をさがす | 陽太AI（AI営業） | 会場一覧＋問い合わせメールの下書き |
| スポンサー候補をさがす | 陽太AI（AI営業） | 企業一覧＋協賛依頼メールの下書き |
| 調べてメモを作る | 知也AI（AIリサーチャー） | 調査結果＋社内共有用の文章 |

- AIが検索キーワードを3〜4個考え、**Tavily / Brave** で実際にWeb検索します
- 各項目に**出典URL**と**確度（高／中／要確認）**が付きます
- 結果はテキストで保存、またはタスクとして登録できます

環境変数 `TAVILY_API_KEY` / `BRAVE_API_KEY`（どちらか片方でも可）。
`SEARCH_ROTATE=1` で両方を交互に使い、合計月3,000回まで無料になります。

**注意**：料金や連絡先は変わりやすいので、連絡前に必ず出典URLで確認してください。

## 仕事の進捗状況（画面⑤）

ヘッダーの **「進捗状況」** から開けます。4つのタブに分かれています。

### ①全体進捗
タスク完了率・期限切れ件数・AI社員の稼働・手空きの人数を上段に。
その下にプロジェクト進捗と、部門別（コア部門／メンバーAI／運営スタッフ）の進み具合。

### ②メンバー別進捗
23人のカードが並び、それぞれの完了率と進行中の件数が見えます。
**メンバーをクリックすると、その人のタイムスケジュールが期限順に縦の年表で表示されます。**
「あと3日」「2日超過」のように残り日数が出て、その場で完了にできます。

### ③タスク詳細
全タスクを一覧で確認。すべて／未着手／進行中／完了／期限切れで絞り込めます。
担当者・状態・期限・残り日数・優先度が1行で分かります。

### ④仕事の指示
左で「誰に・何を・いつまでに・優先度」を選んで指示を出します。
右に**担当者ごとのリスト項目**で指示が並び、チェックで完了にできます。
出した指示は、担当者のタイムスケジュールとタスク管理にも反映されます。

## 文字の大きさ（100% / 140% / 180% / 280%）

画面右上の **「文字 A A A A」** で、いつでも切り替えられます。
設定画面（ヘッダーの「設定」）からは、**標準 / 大 / 特大 / 最大** の大きなボタンで選べます。

| 表示 | 倍率 | どうなるか |
| --- | --- | --- |
| 標準 | 100% | 通常の表示 |
| 大 | 140% | 段組みが縦並びになり、横スクロールが出ません |
| 特大 | 180% | パネル内の細かい並びも2列に減ります。スクロール枠の高さ制限も外れます |
| 最大 | 280% | すべて1列。かなり大きな文字でも読めます |

- 選んだ大きさは **この端末に記憶されます**（次に開いたときも同じ大きさ）
- キーボードでも変えられます：**Ctrl + Shift + ↑** で大きく、**Ctrl + Shift + ↓** で小さく
- 文字だけでなくボタンやアイコンも一緒に大きくなるので、押しやすくなります
